文系出身者のための「アルゴリズムとフローチャート」理解度チェック（全10問）

1. はじめに：論理的思考を可視化する重要性

ITの世界へ足を踏み入れる際、多くの人が「プログラミング言語」の習得を急ぎがちですが、ベテランの視点から言えば、言語以上に重要なのが「問題を解くための段取り」、すなわちアルゴリズムを構築する能力です。

アルゴリズムとは、特定の課題を解決するための「厳密な手順」を指します。これを、小説のプロット（構成案）を作るように、言語に依存しない形で視覚化したものがフローチャート（流れ図）です。設計図なしに家を建てられないのと同様、フローチャートは実装における戦略的な「地図」となります。

フローチャートを支える4つの基本シンボル

アルゴリズムを記述するための標準的な記号には、以下の役割があります。

1. 矢印（Arrow）: 処理が進む「方向」を示し、全体の流れを導く羅針盤です。
2. 長方形（Rectangle）: 「計算」や「値の代入」といった順次処理（SEQUENCE）を表現します。
3. ひし形（Diamond）: 「もし～ならば」という条件分岐（IF-THEN-ELSE）を司ります。
4. 円または楕円（Terminal）: 処理の「開始」や「終了」を示します。
  * 補足：歴史的な記述（Wikipedia等）では、小さな「点」や「円」を論理的な結合（OR-tie）や状態の変わり目として用いる場合がありますが、現代の入門レベルでは端子として覚えるのが一般的です。

【So What?：曖昧さの排除という「文系力」の活用】

記号の種類を覚えること以上に重要なのは、これらを組み合わせて「曖昧さを排除する」能力です。文系出身者が得意とする「論理の整合性をチェックする力」は、エンジニアリングにおける最大の武器になります。誰が読んでも、どのコンピュータが実行しても同じ結果に辿り着くよう手順を整理することは、実務における認識のズレを最小化し、自動化の確実な基盤を築くことにつながるのです。

それでは、まずは基本記号の役割を実務シナリオを通して確認してみましょう。

1. 処理の進む方向を示す「矢印」

3. 判断と分岐を司る「ひし形」

在庫管理システムのフローを記述する際のルールとして、誤っているものはどれですか。

「長方形はアクション」「ひし形はイエスかノーかの決断」と役割が明確です。特に問3の分岐ラベルは、実務において「曖昧さの排除」に直結する非常に重要なポイントです。ラベルがないフローチャートは「どちらに進むべきか」の解釈を読み手に委ねてしまい、バグの温床となります。

3. 第2部：探索アルゴリズムのロジック（問4〜問6）

問4

1. 二分探索（Binary Search）
2. 線形探索（Linear Search）
3. ハッシュ探索
4. 選択ソート

問5

非常に効率的な探索手法である二分探索（Binary Search）必須の前提条件はどれですか。

1. データの総数が偶数であること。
2. データが「昇順」や「降順」に整列（ソート）されていること。
3. すべてのデータが文字列ではなく数値であること。
4. 探索範囲が常に100件以下であること。

問6

二分探索において、中央の値と探したい値を比較した後の動きとして正しいものはどれですか。

1. 探したい値が中央値より大きければ、中央より「左側」の半分を次の探索範囲にする。
2. 中央の値が一致しなかった場合、残りのすべてのデータを1つずつ確認する。
3. 探したい値が中央値より小さければ、中央より「右側」の半分を捨て、「左側」の半分に絞り込む。
4. 常にリストの先頭3要素だけを残して、残りをすべて捨てる。

【So What?：効率性の違いと辞書のメタファー】

探索の効率は、データ量 n に対してどれだけ手間がかかるか（Big O記法）で考えます。

* 線形探索 (O(n)): 100万件のデータがあれば、最悪100万回のチェックが必要です。
* 二分探索 (O(\log n)): 100万件あっても、中央で範囲を半分に絞り続けるため、わずか約20回のチェックで済みます。

これを日常生活に例えるなら、辞書を引く動作です。1ページ目からめくるのが線形探索、真ん中あたりを開いて「目当ての単語が前か後ろか」を確認して範囲を絞るのが二分探索です。この「賢い手順」の差が、システムのレスポンス速度を決定づけます。

問9

「お礼状を100枚印刷する」という繰り返し処理（ループ）を設計する際、プログラムが止まらなくなる「無限ループ」を防ぐために、フローチャートに必ず組み込むべき要素は何ですか。

バブルソートや選択ソートは、仕組みが直感的で実装しやすい反面、データ量が増えると処理時間が急激に増大します（O(n^2)）。

* 選択ソートのメタファー: 「散らかった財布の中から最小の硬貨を探して端に置く」という動作は分かりやすいですが、硬貨が1万枚あれば探す手間は膨大です。 単純な手法が「悪い」わけではありません。データが少なければシンプルさが正義であり、膨大であればマージソートのような「効率的だが複雑な（メモリを消費する）」手法が選ばれます。ビジネスの現場と同様、ITでも「コスト（時間とメモリ）」と「効果」のトレードオフを判断する視点が不可欠です。

5. 第4部：実践的アルゴリズムの応用（問10）

問10

古代から伝わる、2つの数の最大公約数を求めるユークリッドの互除法（引き算や割り算を繰り返す手順）において、処理が終了し、解が求まったと判断される「状態」はどれですか。

1. 計算の途中で数値が負の数（マイナス）になったとき。
2. 2つの数値を比較して、その差または余りが「0」になったとき。
3. 計算のステップ数が、元の数値の和を超えたとき。
4. 片方の数値が、もう片方の数値の2倍になったとき。

【So What?：数学的厳密さと現代の挑戦】

アルゴリズムの定義には「有限のステップで解を出す」という数学的厳密さが含まれます。ユークリッドの互除法は紀元前から続く「変わらぬ論理」の代表例です。 しかし現代では、この「論理の堅牢さ」が新たな局面にあります。NIST（米国国立標準技術研究所）がポスト量子暗号の標準化を進めているように、従来のアルゴリズムの前提（計算の困難さ）が量子コンピュータによって脅かされる可能性が出てきたのです。それでも、根底にある「決められた終了条件に向けて確実に歩を進める」という知恵は、技術が変わっても不変の価値を持ち続けます。

1. イントロダクション：フローチャートの戦略的重要性と基本記号

フローチャートは単なる「図」ではありません。コンピュータに命令を出す前に、自分の「思考」を整理し、ミスがないかを確認するための戦略的な設計図です。

これは日常生活の「料理のレシピ」や「駅までの道案内」に非常に似ています。「野菜を切る」という具体的なアクションや、「もし信号が赤なら止まる」という判断。これらを曖昧さなく並べたものがアルゴリズムです。フローチャートという共通言語を使うことで、私たちは自分の考えを誰にでも（そしてコンピュータにも）正確に伝えることができるようになります。

基本記号の定義と役割

ソースコンテキストに基づき、まずはこれだけは覚えておきたい4つの武器を紹介します。

端子（開始・終了）： 角の丸い長方形です。物語の「はじまり」と「おわり」を示します。
処理（長方形）： 「計算する」「代入する」といった具体的なアクションを表します。
判断（ひし形）： 「もし～なら」という分岐点です。ここから道が分かれます。
線（矢印）： 命令が流れる方向を示します。

【演習問題 1】記号の識別

A) 長方形
B) ひし形

分析レイヤー： この「ひし形」は、アルゴリズムの「自動意思決定（Automated decision-making）」を司る心臓部です。人間がいちいち指示を出さなくても、コンピュータがデータを見て「自ら判断する」ためのロジックをここに組み込みます。

次は、この「判断」が現代のプログラミングでどう表現されるのかを見てみましょう。

2. 選択構造：判断と分岐のロジックをマスターする

コンピュータの「知能」の正体は、実は単純な「YesかNoか」の積み重ねです。これを「if-then-else（選択構造）」と呼びます。

【重要：現代の記述スタイル】 日本の基本情報技術者試験などの最新基準（2023年改訂）では、かつての日本語を多用した形式から、より実務に近い形式へと劇的に変化しました。以前は「もし～ならば」と縦線で範囲を示していましたが、現在は if / endif というキーワードで囲む形が標準です。皆さんがこれから目にする「実戦的な設計図」はこのスタイルです。

【演習問題 2】分岐のトレース（追跡）

以下のロジック（if構造）において、入力値 A = 50 の時の出力はどうなるでしょうか？

ロジック： if (A が 50 以上) 　　「合格」と表示 else 　　「不合格」と表示 endif

選択肢：
  * A) 合格
  * B) 不合格
  * C) エラー
  * D) 何も表示されない

分析レイヤー（ビジネスの視点）： プログラミングの世界では「50ちょうど」のような境界線の扱いが極めて厳密です。例えば、「5,000円以上のお買い上げでクーポン適用」というビジネスルールを設計した際、5,000円の人を誤って対象外にしてしまうと、それはシステムの信頼性に関わります。コンピュータは「忖度（そんたく）」をしません。私たちが数学的に厳密な定義を与えることが、バグ（不具合）を防ぐ唯一の道なのです。

3. 反復構造：効率的な自動化を実現するループ処理

コンピュータの最大の強みは「飽きずに、間違えず、超高速で繰り返す」ことです。これを「反復（ループ）」と呼び、while / endwhile という記号（現代形式）で表現します。

人間が100万回の計算をすると必ずミスをしますが、コンピュータはアルゴリズムに従って同じ作業を完璧にこなします。この「実行効率（Execution efficiency）」の差こそが、自動化の価値です。

終了条件と「システムのスナップショット」

ループを設計する際、最も重要なのが「いつ止めるか（終了条件）」です。これを忘れると、コンピュータは永遠に計算を続ける「無限ループ」に陥ってしまいます。 アルゴリズムを理解するには、変数の値が刻一刻と変化していく様子を「Successive states（連続する状態＝システムのスナップショット）」として捉えるのがコツです。

【演習問題 3】カウント変数の変化

変数 i を使った以下のループを考えます。ループを抜けた直後の i の値はいくつでしょうか？

ループ内容：

1. i ← 0 （最初に0を代入）
2. while (i < 10) ―― つまり「iが10より小さい間」繰り返す
3. 　　i ← i + 1
4. endwhile

選択肢：
  * A) 9
  * B) 10
  * C) 11
  * D) 0

分析レイヤー（効率の概念「Big O」）： ここで少し「効率」の話をしましょう。例えば100万人の電話帳から一人を探すとき、1ページずつめくると最悪100万ステップかかりますが、半分ずつ絞り込む（バイナリサーチ）とわずか20ステップで済みます。これを専門用語で「Big O記法」と呼び、入力データが増えた時にどれだけ手間（計算量）が増えるかを評価する指標にします。優れたアルゴリズムは、この「手間」を最小限に抑えるのです。

4. アルゴリズムの応用：探索と最大値の特定

これまで学んだ「順次」「選択」「反復」という基本ブロックは、いわば「レゴブロック」です。これらを組み合わせることで、「バラバラのデータから最大値を見つける」といった実用的なアルゴリズムを組み立てることができます。

アルゴリズムの組み立て

例えば、複数のロッカー（配列）の中から一番大きな数字を探す「LargestNumber」というアルゴリズム。これは、一つひとつのロッカーを開けて中身を確認し、今の暫定1位と比較して更新し続けるという手順の積み重ねです。

【演習問題 4】最大値特定アルゴリズム

リスト [10, 50, 20] を、以下の「LargestNumber」アルゴリズムで処理します。この過程で「暫定の最大値（largest）」という変数の値が「書き換え（更新）」される回数は、最初の初期設定を除いて何回でしょうか？

アルゴリズム手順：

1. リストの最初の数（10）を、まず「最大値（largest）」とする。
2. 残りの数（50, 20）を順番にチェックする。
3. もし「今の数」が「largest」より大きければ、その数で「largest」を上書きする。

選択肢：
  * A) 0回
  * B) 1回
  * C) 2回
  * D) 3回

分析レイヤー（トレースの重要性）： 複雑な問題を解決する秘訣は、問題を小さく分解し、一歩ずつ変数の動きを「トレース（追跡）」することにあります。この「地道な確認」こそが、どんな複雑なソフトウェアも支えているのです。

ステップバイステップ解説

【演習 1】

解説： 分岐を司る「ひし形」は、コンピュータにおける「もし～なら（IF）」を表現します。ここからYes/Noの2本の道が出ることで、状況に応じた自動判断が可能になります。

【演習 2】

解説： 「以上」はその数値を含みます。A=50は条件を満たすため「合格」へ進みます。プログラミングでは >（超過）か >=（以上）かといった細かな記号の使い分けが、システムの正確性を決定づけます。

【演習 3】

解説： i が9の時は条件（i < 10）を満たすのでループ内へ入り、i は10になります。その後、再び条件を確認すると「10 < 10」は成立しない（偽）ため、ここで初めてループを抜けます。抜けた瞬間の i は「10」です。

【演習 4】

解説： 変数の変化（Successive states）をトレーステーブルで見てみましょう。

ステップ	チェックする数	比較ロジック	結果 (largestの値)	更新の有無
初期設定	10	(なし)	10	－
1回目	50	50 > 10 ? (Yes)	50	更新あり
2回目	20	20 > 50 ? (No)	50	更新なし

最初の設定を除くと、更新は「50」に書き換わった時の1回のみです。このように、一歩ずつのスナップショットを撮ることで、複雑なロジックも確実に理解できるようになります。
