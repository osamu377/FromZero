ダイクストラ法を効率的に実行するためには、**「未確定の地点の中で最も距離が短いもの」** を素早く見つける必要があります。ここで、前回学んだ**「ヒープ（優先度付きキュー）」**が最高のパートナーになります。

ヒープを使わない場合、毎回すべての地点を調べるため計算量が膨らみますが、最小ヒープを使えば常に最小値を  で取り出せます。

---

## 1. 疑似言語によるアルゴリズム

基本情報技術者試験の記法をベースにした、ヒープ活用のダイクストラ法です。

```text
○関数 Dijkstra(グラフ G, 開始頂点 start)
| ○優先度付きキュー: PQ  /* 最小ヒープ: (距離, 頂点) のペアを保持 */
| ○配列: dist[]         /* 各頂点への最短距離を保存 */
|
| /* 1. 初期化 */
| 各頂点 v について:
|   dist[v] ← 無限大
| dist[start] ← 0
| PQ.push(0, start)
|
| /* 2. 探索ループ */
| ■ PQ が空でない間 繰り返す
| | (d, u) ← PQ.pop()  /* 現在、最も距離が短い頂点 u を取り出す */
| |
| | ▲ d > dist[u]
| | | 継続 (continue)  /* すでに確定済みのより短い経路があれば無視 */
| | ▼
| |
| | ■ 頂点 u に隣接する各頂点 v について 繰り返す
| | | ○新距離: new_dist ← dist[u] + 辺(u, v)のコスト
| | |
| | | ▲ new_dist < dist[v]
| | | | dist[v] ← new_dist
| | | | PQ.push(new_dist, v)  /* 短い経路が見つかったらヒープに追加 */
| | | ▼
| | ■
| ■
| 戻り値 dist

```

---

## 2. 処理のポイント解説

### なぜヒープ（PQ）が必要か？

ヒープを使わない単純な配列管理だと、次に調べる頂点を探すのに毎回全頂点をスキャンするため、非常に時間がかかります。ヒープを使えば、**「次に確定すべき頂点」が自動的に頂上に浮上してくる** ため、無駄がありません。

### `d > dist[u]` の判定（スキップ処理）

ヒープには、同じ頂点への「古い（長い）距離の情報」が残っていることがあります。すでにもっと短い距離で確定している場合は、古い情報を無視することで計算を高速化します。

## 4. 学習のアドバイス

試験や実習でこのアルゴリズムを追うときは、**「確定した距離のリスト」** と **「ヒープの中身」** を別々にメモしながら進めるのがコツです。

1. ヒープから一番小さい値を取り出す。
2. その隣接ノードを計算し、短ければヒープに放り込む。
3. 1に戻る。

このリズムを意識すると、コードの動きが手に取るように分かります。
