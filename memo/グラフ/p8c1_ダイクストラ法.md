# ダイクストラ法

グラフアルゴリズムの中で最も有名で、かつ実用的なのが **ダイクストラ法（Dijkstra's Algorithm）** です。

一言でいうと、**「スタート地点から、他のすべての地点（または特定のゴール）までの最短距離を求める」** ためのアルゴリズムです。Google マップのルート検索の裏側でも、この考え方が応用されています。

---

## 1. ダイクストラ法の基本ルール

このアルゴリズムは、**「重み付きグラフ（辺にコストがあるグラフ）」** に対して使われます。ただし、一つだけ重要な制約があります。

> **制約：** すべての辺のコストが「0以上」であること。（マイナスのコストがあると正しく動かないため、別のアルゴリズムが必要になります）

---

## 2. アルゴリズムの仕組み（直感的なイメージ）

「自分に近いところから順に、最短距離を確定させていく」というステップを繰り返します。

### ステップ：

1. **初期化：**
* スタート地点の距離を「0」、それ以外を「無限大（）」にする。


2. **探索：**
* まだ「確定」していない地点の中で、**最も距離が短い地点** を選び、そこを「確定」とする。


3. **更新（緩和）：**
* 確定した地点から行ける隣の地点の距離を計算し、今の値より短くなるなら書き換える。


4. **繰り返し：**
* すべての地点が「確定」するまで、2と3を繰り返す。



---

## 3. 具体的な例で考える

A駅からD駅までの最短時間を求めるとします。

1. **スタート A(0)**、他の駅は 。
2. Aから行けるのは B(10分) と C(30分)。
3. 未確定の中で一番近い **B(10分)** を確定！
4. Bから行けるDまでの時間を計算。A→B(10分) + B→D(50分) = **計60分**。
5. 次に近いのは **C(30分)**。Cを確定！
6. Cから行けるDまでの時間を計算。A→C(30分) + C→D(10分) = **計40分**。
7. もともとのDの候補（60分）より短いので、**Dは40分に更新！**
8. 最後に **D(40分)** を確定して終了。

---

## 4. 特徴と計算量

* **確実性：** 「その時点で一番近いところ」を順に確定していくため、一度確定した距離が後からもっと短くなることはありません（これが「負のコスト」がない前提で成り立つ理由です）。
* **計算量：** 実装によりますが、優先度付きキュー（ヒープ）を使うと、頂点数を 、辺の数を  としたとき  で計算できます。これは非常に高速です。

---

## 5. 実社会での応用例

* **カーナビ・地図アプリ：** 最短時間・最短距離のルート探索。
* **ネットワークのルーティング：** インターネット上でパケットをどの経路で送るかの決定（OSPFプロトコルなど）。
* **ゲームAI：** 敵キャラクターがプレイヤーにたどり着くための最短ルート計算。

ダイクストラ法を効率的に実行するためには、**「未確定の地点の中で最も距離が短いもの」** を素早く見つける必要があります。ここで、前回学んだ**「ヒープ（優先度付きキュー）」**が最高のパートナーになります。

ヒープを使わない場合、毎回すべての地点を調べるため計算量が膨らみますが、最小ヒープを使えば常に最小値を  で取り出せます。

## 1. 疑似言語によるアルゴリズム

基本情報技術者試験の記法をベースにした、ヒープ活用のダイクストラ法です。

```text
○関数 Dijkstra(グラフ G, 開始頂点 start)
| ○優先度付きキュー: PQ  /* 最小ヒープ: (距離, 頂点) のペアを保持 */
| ○配列: dist[]         /* 各頂点への最短距離を保存 */
|
| /* 1. 初期化 */
| 各頂点 v について:
|   dist[v] ← 無限大
| dist[start] ← 0
| PQ.push(0, start)
|
| /* 2. 探索ループ */
| ■ PQ が空でない間 繰り返す
| | (d, u) ← PQ.pop()  /* 現在、最も距離が短い頂点 u を取り出す */
| |
| | ▲ d > dist[u]
| | | 継続 (continue)  /* すでに確定済みのより短い経路があれば無視 */
| | ▼
| |
| | ■ 頂点 u に隣接する各頂点 v について 繰り返す
| | | ○新距離: new_dist ← dist[u] + 辺(u, v)のコスト
| | |
| | | ▲ new_dist < dist[v]
| | | | dist[v] ← new_dist
| | | | PQ.push(new_dist, v)  /* 短い経路が見つかったらヒープに追加 */
| | | ▼
| | ■
| ■
| 戻り値 dist

```

---

## 2. 処理のポイント解説

### なぜヒープ（PQ）が必要か？

ヒープを使わない単純な配列管理だと、次に調べる頂点を探すのに毎回全頂点をスキャンするため、非常に時間がかかります。ヒープを使えば、**「次に確定すべき頂点」が自動的に頂上に浮上してくる** ため、無駄がありません。

### `d > dist[u]` の判定（スキップ処理）

ヒープには、同じ頂点への「古い（長い）距離の情報」が残っていることがあります。すでにもっと短い距離で確定している場合は、古い情報を無視することで計算を高速化します。

## 4. 学習のアドバイス

試験や実習でこのアルゴリズムを追うときは、**「確定した距離のリスト」** と **「ヒープの中身」** を別々にメモしながら進めるのがコツです。

1. ヒープから一番小さい値を取り出す。
2. その隣接ノードを計算し、短ければヒープに放り込む。
3. 1に戻る。

このリズムを意識すると、コードの動きが手に取るように分かります。
