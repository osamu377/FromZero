# Chapter 8

「探索（たんさく）」とは、たくさんのデータの中から「目的のデータがどこにあるか」を見つけることです。

今回は、最もシンプルな見つけ方である「線形探索」と、少し応用編の「文字列の探索」について、身近な例で解説します。

---

## 1. 配列中の文字探索（線形探索）

「線形探索（せんけいたんさく）」は、別名「しらみつぶし探索」とも呼ばれます。端から順番に一つずつチェックしていく、最も原始的で確実な方法です。

* **例え：バラバラに並んだ「トランプ」から「エース」を探す**
1. 一番左のカードをめくる。
2. エースじゃなければ、次のカードをめくる。
3. エースが見つかるまで、右へ右へと順番に繰り返す。



### 疑似言語でのイメージ

5つの文字が入った配列 `data` から、「C」という文字を探す流れです。

```text
整数型: data[5] = {'A', 'B', 'C', 'D', 'E'}
文字型: target ← 'C'
整数型: i, position
position ← 0  // 見つからなかった時のための印

for (i を 1 から 5 まで 1 ずつ増やす)
    if (data[i] ＝ target)
        position ← i  // 何番目にあったか記録
        break         // 見つかったのでループを抜ける
    endif
endfor

```

## 2. ２文字以上の文字列をキーにした文字列探索

次は、「長い文章（文字列）」の中から「特定の言葉（文字列）」を探す方法です。単なる1文字の探索より少しだけ工夫が必要です。

* **例え：長い手紙の中から「ありがとう」という言葉を探す**
1. まず、手紙の1文字目を見る。
2. 1文字目が「あ」だったら、その次の文字が「り」かどうか見る。
3. 「ありがと……」と順番に見ていって、最後まで一致したら発見！
4. もし途中で違ったら（例えば「ありな……」など）、**手紙の「次の1文字」から**また「あ」を探し直す。



### 動きのポイント：窓をずらす

長い文章の上に、探したい言葉が書かれた「透明な窓」を置いて、1文字ずつ右にずらしながら覗き込むイメージです。

### 疑似言語での考え方（簡略版）

文章 `text`（10文字）の中から、単語 `key`（3文字）を探す場合：

```text
// 外側のループ：文章のどこからチェックし始めるか
for (i を 1 から (10 - 3 + 1) まで 1 ずつ増やす)
    
    // 内側のループ：i番目から始まる3文字が、keyと一致するか
    // ここで「2文字以上の一致」を1文字ずつチェックする！
    if (文章の i番目からの3文字 ＝ key)
        「見つかりました！」と表示
    endif

endfor

```

## 3. なぜ「2文字以上」だと難しいの？

1文字の探索と違い、文字列の探索は「惜しい！」という状態が起きるからです。

* 文章：`ABABC`
* 探し物：`ABC`

1. 最初は `ABA` まで一致して「惜しい！」となりますが、3文字目が `B` と `C` で違うため失敗です。
2. 次に、1文字ずらして `BAB` をチェックします。
3. さらに1文字ずらして `ABC` をチェックし、ここでようやく発見となります。

このように、「外側のループ（開始位置をずらす）」**と**「内側のループ（その位置から単語が一致するか調べる）」の二重構造になるのが特徴です。

---

## まとめ

* **線形探索** ＝ 先頭から順番に1つずつ「これかな？」と確認していく方法。
* **文字列探索** ＝ 探し物の長さ分だけ「窓」を作って、重なる場所をずらしながら探す方法。

どちらも「見つかるまで繰り返す」というアルゴリズムの基本が詰まっています。この仕組みが、皆さんのスマホの「ページ内検索」などで実際に動いているんですよ！
